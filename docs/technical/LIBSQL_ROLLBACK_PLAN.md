## 概述

### 回退目标

在 libsql 迁移后，如果发现问题，能够：
- ✅ 快速回滚到迁移前的状态（< 1 分钟）
- ✅ 验证回滚后的数据完整性
- ✅ 确保系统恢复正常运行

### 回退原则

1. **快速回滚**：回滚时间 < 5 分钟
2. **数据完整性**：回滚后数据与迁移前一致
3. **可重复**：回退过程可重复执行
4. **可验证**：回滚后必须验证数据完整性

## 回退场景

### 场景 1：数据迁移失败

**症状**：
- 迁移脚本报错
- 数据库文件损坏
- 数据量严重不一致（>5% 差异）

**影响**：高
**优先级**：最高

### 场景 2：性能显著下降

**症状**：
- 首次检索时间 > 5s
- 后续检索时间 > 0.5s
- 数据库文件大小异常（>20GB）

**影响**：中
**优先级**：高

### 场景 3：功能异常

**症状**：
- 搜索功能返回错误
- Wiki 查询失败
- CLI 命令无法执行

**影响**：中
**优先级**：中

### 场景 4：系统不稳定

**症状**：
- 服务频繁崩溃
- 数据库连接失败
- 内存占用过高

**影响**：高
**优先级**：最高

## 回退步骤

### 步骤 1：停止服务

```bash
# 停止 RAG 服务
python scripts/rag_cli.py service stop

# 验证服务已停止
python scripts/rag_cli.py status
```

### 步骤 2：运行回滚脚本

```bash
# 运行回滚脚本
python scripts/rollback_libsql.py
```

回滚脚本会：
1. 查找最新的备份目录
2. 恢复 ChromaDB 数据
3. 恢复 SQLite 数据
4. 恢复 LSH 索引
5. 恢复全局计数器
6. 清理旧备份（保留 3 个最新）

### 步骤 3：验证回滚结果

```bash
# 运行验证脚本
python scripts/verify_migration.py

# 检查服务状态
python scripts/rag_cli.py status

# 测试搜索功能
python scripts/rag_cli.py search "方源"
```

### 步骤 4：重启服务

```bash
# 重启 RAG 服务
python scripts/rag_cli.py service start

# 验证服务已启动
python scripts/rag_cli.py status
```

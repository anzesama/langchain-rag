# RAG 系统重构计划

> 评审日期：2026-06-30
> 目标：从"实验室 Demo"走向"生产级工具"

---

## P0：增量更新机制（最高优先级）

### 目标
让知识库"活"起来，无需重建即可添加/删除文档。

### 任务清单

- [ ] **任务 1**：实现 `/api/upload` 接口
  - 支持单个文件上传（PDF/MD/TXT/DOCX）
  - 返回 `document_id` 和 `status: pending`
  - 不阻塞主业务流程

- [ ] **任务 2**：实现异步向量化管道
  - 上传后触发后台任务
  - 文档状态机：`pending → processing → completed/failed`
  - 失败可重试，成功通知客户端

- [ ] **任务 3**：实现 `/api/documents/{id}` 接口
  - 查询文档状态
  - 查看文档详情（标题、页数、chunk 数、状态）
  - 支持删除文档

- [ ] **任务 4**：实现批量上传
  - 支持目录扫描 + 增量检测（基于文件修改时间）
  - 只处理新增/更新的文档

### 技术设计

```
用户上传 → API 接收 → 存入临时目录 → 返回 document_id
                                    ↓
                            后台任务队列（Redis Streams）
                                    ↓
                            文档解析 → 语义切分 → 向量化 → 存入 ChromaDB
                                    ↓
                            更新状态为 completed
```

## P1：语义级文档切分 + 质量评估

### 目标
提升检索质量，建立可量化的评估体系。

### 任务清单

- [ ] **任务 5**：实现语义切分
  - 按标题层级切分（H1/H2/H3）
  - 保留页码、章节元数据
  - 递归细切过长段落
  - 合并过短片段

- [ ] **任务 6**：构建离线评估数据集
  - 准备 50+ 个问题-答案-相关文档对
  - 包含边界情况（无答案、多答案、模糊答案）

- [ ] **任务 7**：实现质量评估指标
  - Recall@K（召回率）
  - Precision@K（精确率）
  - MRR（平均倒数排名）
  - Faithfulness（答案忠实度）

- [ ] **任务 8**：建立评估脚本
  - `python evaluate.py --dataset test_set.json`
  - 输出报告 + 可视化图表

## P2：混合检索 + 缓存

### 目标
提升检索准确性和性能。

### 任务清单

- [ ] **任务 9**：实现 BM25 关键词检索
  - 与向量检索并行
  - 结果融合（RRF 排序）

- [ ] **任务 10**：实现 Rerank 模型
  - 对 Top-20 向量检索结果重排序
  - 返回 Top-5 给 LLM

- [ ] **任务 11**：实现查询缓存
  - 高频查询结果缓存（LRU）
  - 缓存过期策略（5 分钟 TTL）
  - 缓存命中率监控

## P3：微服务拆分 + 安全 + 监控

### 目标
提升系统可用性和安全性。

### 任务清单

- [ ] **任务 12**：拆分写入服务
  - `doc_processor.py` — 文档解析、切分、向量化
  - 与 `rag_server.py` 解耦

- [ ] **任务 13**：拆分读取服务
  - `search_service.py` — 向量检索、混合检索、Rerank
  - 可独立扩展

- [ ] **任务 14**：实现身份验证
  - API Key 认证
  - 可选：JWT Token

- [ ] **任务 15**：实现输入/输出过滤
  - Prompt Injection 检测
  - 敏感词过滤
  - 输出安全审查

- [ ] **任务 16**：实现审计日志
  - 记录所有查询（时间、用户、问题、结果数）
  - 支持日志导出和分析

- [ ] **任务 17**：实现健康检查
  - `/health` 端点
  - 监控模型加载状态、向量库状态、缓存命中率

## 验收标准

### P0 完成标准
- [ ] 上传单个 PDF，30 秒内完成向量化
- [ ] 查询文档状态，实时可见
- [ ] 批量上传 10 个文档，全部成功入库
- [ ] 删除文档后，检索不再返回该文档

### P1 完成标准
- [ ] 语义切分比固定切分 Recall@5 提升 ≥20%
- [ ] 评估脚本可重复运行，输出稳定
- [ ] MRR ≥ 0.7（基于测试集）

### P2 完成标准
- [ ] 混合检索比纯向量检索 Precision@5 提升 ≥15%
- [ ] 缓存命中率 ≥ 30%（高频查询场景）
- [ ] 检索响应时间 ≤ 2s（含缓存命中）

### P3 完成标准
- [ ] 无 API Key 请求返回 401
- [ ] 敏感查询被拦截并记录
- [ ] 审计日志可查询、可导出
- [ ] 写入服务崩溃不影响读取服务

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| Redis Streams 引入复杂度 | 运维成本增加 | 先用内存队列，后期迁移 |
| 语义切分实现困难 | 检索质量不升反降 | 保留固定切分作为 fallback |
| Rerank 模型加载慢 | 检索延迟增加 | 预加载 + 缓存 |
| 微服务拆分导致数据不一致 | 检索结果错误 | 使用唯一 document_id，事务保证一致性 |
